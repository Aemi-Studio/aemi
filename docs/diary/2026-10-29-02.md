## Directory walking, measured before an API (analyzerkit roadmap 0006, ADR 0017)

the tree as analyzerkit's `SourceDiscovery` does (skips `.build`, `.git`, `DerivedData`, `.swiftpm`, `checkouts`, hidden

| Question | Probe | Verdict |
|---|---|---|
| Does `getattrlistbulk` beat `readdir` + `d_type`? | the table | **Only warm, and slightly.** Cold, and on a large directory, it is slower. |
| Why is `getattrlistbulk` 150× slower on the 267,000-entry directory? | buffer 16 KiB to 1 MiB; `lstat` of 20,000 of its entries twice | **It reads every entry's inode.** The buffer changes nothing (20.6–20.8 s); a first `lstat` costs 89 µs per entry, a second 2 µs. `kern.maxvnodes` is 251,343 and full, so a directory larger than the vnode cache evicts its own entries and stays cold on every run. `readdir` returns names and types from the directory records alone. `FileManager.contentsOfDirectory` costs the same as `getattrlistbulk` (22.9 s). |
| Cold, on a source tree? | stat every entry of the 267,000-entry directory before each run, which evicts the corpus's vnodes | **readdir still wins**: 93 ms against 130 ms single-threaded, 35.6 against 41.2 ms on four workers; today's method 325 ms. |
| Descriptors per worker? | the most directories ever queued | **Too many to hold open.** The queue peaks at 272 (one worker) to 440 (eight) directories on maintastic, 35–50 on swift-syntax. A descriptor per queued directory exceeds launchd's default soft limit of 256 (`launchctl limit maxfiles`). Sequential descent holds the depth (10). |
| Can a queued path be opened safely without holding its parent? | `openat(root, "link/sub", O_DIRECTORY \| O_NOFOLLOW_ANY)` with `link` a symlink | **Yes, on Darwin.** `O_NOFOLLOW_ANY` refuses a link anywhere in the path (ELOOP); `O_NOFOLLOW` alone follows the intermediate link. |

Not measured here: Linux (`getdents64`, `openat2` with `RESOLVE_NO_SYMLINKS`); a cold run of the 267,000-entry directory with
`readdir`, which cannot be made cold without root; a quiet machine.
