# 2026-10-29 (03) — The interner, measured first (analyzerkit roadmap 0015)

## Inputs

Two key streams from maintastic, in the order a tool meets them, dumped by throwaway tests in deadwood (not committed):
the USR of every occurrence in its index store, file by file (661,234 occurrences, 120,256 distinct, 120 bytes on
average; the store copied to `/tmp` first, since reading it creates an `IndexDatabase` beside it), and the text of every
token SwiftParser gives for its Swift files (1,123,010 occurrences, 30,209 distinct, 4.8 bytes per occurrence and 21 per
distinct key).

with four performance and four efficiency cores; two whole runs agreed within 3%.

## A bug in the probe, and how the hash was checked

The first run had wyhash interning tokens at 36.6 ms although it hashed them fastest. I had written its seed setup as
`mix(s0 ^ s0, s1)`, which is zero, so a key under four bytes hashed by its length alone and the token table degenerated.
Fixed to `mix(seed ^ s0, s1)`; then checked against the reference `wyhash.h` (fetched, compiled with clang): its seven test
vectors match once each is hashed with its index as seed, as `test_vector.cpp` does (my memory of one constant was wrong,
the reference settled it), and lengths 3 to 150 with seed 0 match too. That comparison also caught `i > 48` where the
reference has `i >= 48`, which changes the hash of a key of exactly 48 or 96 bytes. The numbers above are from the
corrected probe.

## Decided

ADR 0019: wyhash in `AemiKernel`; `AemiInterner` with the arena, 32-bit tags in 64-bit slots, `Interner`,
`FrozenInterner`, and the sharded merge. Next: red tests (determinism over worker counts, no allocation per repeated
intern, the serialisation round trip, wyhash's reference vectors), then the build.

## Built

Red: ten tests and nineteen hash vectors against stubs, every one failing. One test crashed the run instead of failing
(it indexed the stub's empty remap table), so its count check became a `#require`; another passed against the stub (an
empty interner round-trips to itself), so it gained an absolute count. Green: `WyHash` in `AemiKernel`, `AemiInterner`
(`Table.swift`, `Interner.swift`, `Merge.swift`). All green, 20 repeated runs clean, ThreadSanitizer clean; aemi's whole
suite (877 tests) passes.

The allocation guard first failed green: two allocations per intern. Measured piece by piece, the interner allocated
nothing; the guard's own loop did (a `for … in` over an array and `Array.withUnsafeBytes`, twice per element, in a
`-Onone` build). The guards now measure one call on bytes made beforehand, as the Base64 guards do. Under
ThreadSanitizer every exit test in aemi aborts, the Base64 ones included; not new.

Package benchmark (`interner/*`, p50), with `AEMI_INTERNER_CORPUS` pointing at the dumps:

| | `[String: UInt32]` | AemiInterner | merged, 4 workers |
|---|---|---|---|
| USRs | 107 ms | 20 ms | 8.1 ms |
| tokens | 37 ms | 19 ms | 7.3 ms |

Slower than the probe on one thread (17.2 and 14.7 ms). The same sources compiled into one module with the probe's harness
give 17.3 and 15.1 ms, equal to the probe; the difference is the call into another module and the benchmark's closure.
Moving WyHash's constants from stored to computed, and its loads from the buffer to its base pointer, changed little.
Without the dumps the benchmark uses seeded streams with no locality, where the merge is no faster than one thread
(ADR 0019, consequences).
